# 三端页面清单

> 版本 v0.1 · 2026-11-16 · 待评审
> 本文档定义每个页面的路由、职责、关键交互与依赖接口。代码实现以此为准。

---

## 一、顾客端小程序（`miniapp`）

### 路由总表

| # | 路由 | 页面 | 是否 tabBar |
|---|---|---|---|
| C1 | `pages/entry/index` | 扫码落地 / 开台 | 否（启动页） |
| C2 | `pages/menu/index` | 点菜主页 | 否 |
| C3 | `pages/dish/index` | 菜品详情 / 选规格 | 否 |
| C4 | `pages/cart/index` | 确认订单 | 否 |
| C5 | `pages/pay-result/index` | 支付结果 | 否 |
| C6 | `pages/orders/index` | 本桌订单 | 否 |
| C7 | `pages/me/index` | 我的（历史订单、客服） | 是 |

页面栈约定：C1 是唯一入口，用 `redirectTo` 进入 C2，避免用户返回后回到开台页重复开台。C2~C6 之间用 `navigateTo`，页面栈深度不超过 5。

---

### C1 扫码落地 / 开台

- **触发**：扫描桌上小程序码，`onLoad` 的 `options.scene` 携带桌号（URL 编码过，需 `decodeURIComponent`）
- **职责**：校验桌台 → 建立或复用会话 → 展示「您已就座 A08」→ 进入菜单
- **关键交互**
  - 调 `openSession({ scene })`，返回 `{ shop, table, session, unpaidOrder }`
  - 若返回 `unpaidOrder`：顶部横幅提示「您有一笔未支付的订单 ¥86.00」，主按钮变为「去支付」
  - 若无 `scene`（用户从历史记录直接进入）：展示「请扫描桌上的二维码」+ 说明图，不提供手动输入桌号（防止绕过）
- **异常分支**

| 服务端返回 | 页面表现 |
|---|---|
| `TABLE_NOT_FOUND` | 「该桌码已失效，请联系服务员」+ 客服按钮 |
| `TABLE_DISABLED` | 「本桌暂停使用，请换一桌」 |
| `SESSION_CLOSED` | 「本桌已结账，如需继续用餐请呼叫服务员」 |
| `SHOP_CLOSED` | 「当前不在营业时间」+ 营业时间 |

- **不再重复开台**：`openSession` 幂等，已有 open 会话直接返回，不新建

---

### C2 点菜主页

- **布局**：左侧分类竖列（锚点联动）+ 右侧菜品列表 + 吸底购物车条
- **关键交互**
  - 分类点击滚动定位，滚动时反向高亮分类
  - 菜品卡片：图片、名称、价格、月售、估清置灰且不可点
  - 无规格菜品点「＋」直接进购物车（一次点击完成，不跳详情）
  - 有规格菜品点卡片进入 C3
  - 吸底条显示总件数、合计金额、「去结算」按钮，点击进 C4
- **加菜态**：若本会话已有「已支付」订单，吸底条上方固定提示「本次为加菜，将生成新订单单独支付」
- **数据**：`getMenu({ shopId })` 一次返回分类与菜品，客户端缓存 5 分钟
- **购物车隔离**：本地 `storage` 的 key 为 `cart:{sessionId}`，换桌或清台后自动清理，防止串单

---

### C3 菜品详情 / 选规格

- **职责**：规格单选、加料多选、数量、单品备注
- **关键交互**
  - 规格与加料数量变化时，价格实时联动（`basePrice + Σ specDelta + Σ addonDelta`）
  - 多规格必选，未选时「加入购物车」置灰
  - 备注输入上限 50 字，敏感词做前端过滤
  - 加入购物车后 `navigateBack`，不弹 toast 打断（吸底条数字跳动即为反馈）
- **说明**：同一菜品不同规格视为不同的购物车行，不能合并数量

---

### C4 确认订单

- **职责**：核对明细、整单备注、提交、唤起支付
- **关键交互**
  - 明细行可加减数量、左滑删除；数量为 0 时自动移除
  - 整单备注上限 100 字（如「不要香菜」「先上凉菜」）
  - 「提交并支付」流程：
    1. 调 `validateCart({ sessionId, items })` —— 服务端校验菜品是否下架/估清，返回最新价格
    2. 价格有变动 → 弹窗告知差异，用户确认后按新价提交
    3. 调 `createOrder` 得到 `orderId` 与 `payParams`
    4. `wx.requestPayment(payParams)`
    5. 成功 → `redirectTo` C5；取消/失败 → `redirectTo` C6 并定位到该待支付订单
  - 提交按钮点击后立即置 loading 且禁用，防止重复下单（幂等键为客户端生成的 `clientToken`）
- **金额安全**：前端展示的合计只用于显示，最终金额以 `createOrder` 返回的 `totalCents` 为准，不一致时以服务端为准并提示

---

### C5 支付结果

- **职责**：确认支付真实性（不信任客户端回调）
- **关键交互**
  - 进入后调 `getOrder({ orderId })` 轮询，最多 5 次、间隔 1 秒
  - 三种状态：已支付（绿色对勾 + 「已通知后厨」）、处理中（转圈 + 「正在确认支付结果」）、未支付（「支付未完成」+ 重新支付）
  - 已支付后展示：桌号、订单号后 6 位、金额、预计出餐时间（若配置）
  - 底部两个按钮：「继续点菜」（回 C2）、「查看订单」（去 C6）

---

### C6 本桌订单

- **职责**：本次用餐的全部订单（首单 + 加菜单）与状态
- **关键交互**
  - 卡片式列表，按创建时间倒序；每张卡片显示：单号尾部、状态、金额、菜品摘要
  - 状态色：待支付（橙）、已支付（蓝）、制作中（蓝）、已出餐（绿）、已退款（灰）
  - 待支付订单显示「立即支付」，点击直接走支付流程，不重新下单
  - 下拉刷新；页面每 30 秒静默刷新一次（前台时）
- **说明**：这里不允许顾客自行取消已支付订单，只能「申请退款」→ 生成退款申请，由管理端处理

---

### C7 我的

- 历史订单（跨桌、跨次）、联系商家（拨号）、隐私协议入口
- 不做会员、不做积分（一期范围外）

---

## 二、管理端小程序（`admin-miniapp`）

### 路由总表

| # | 路由 | 页面 | 权限 |
|---|---|---|---|
| A0 | `pages/login/index` | 登录 / 申请权限 | 无 |
| A1 | `pages/tables/index` | 桌况总览 | waiter 及以上 |
| A2 | `pages/table-detail/index` | 单桌处理 | waiter 及以上 |
| A3 | `pages/order-detail/index` | 订单详情 | waiter 及以上 |
| A4 | `pages/dishes/index` | 沽清 / 上下架 | manager 及以上 |
| A5 | `pages/me/index` | 设置 | 全部 |

### 全局能力（非页面）

**新单提醒是全局的，不是某个页面的事。** 在 `app.js` 的 `onLaunch` 里建立一条对 `order_feed` 集合的 `watch`，任何页面收到新单都触发统一的 `orderAlert` 组件。这样服务员在「桌况」页也会响，不会因为切到「菜品」页而漏单。

- 铃声：`InnerAudioContext` 播放本地铃声，`loop = true` 直到点「接单」或「知道了」
- 亮屏：`wx.setKeepScreenOn({ keepScreenOn: true })`
- 震动：`wx.vibrateLong()`
- 顶部悬浮条：显示「A08 新订单 ¥126 · 4 个菜」+「接单」按钮，任何页面都能点
- 断线重连：`watch` 的 `onError` 触发重连，连续失败 3 次降级为 15 秒轮询

---

### A0 登录 / 申请权限

- `wx.login` → 云函数 `login` 返回 `openid` 与员工信息
- 已在 `staff` 表中 → 按角色跳转（waiter → A1，manager → A1）
- 不在表中 → 显示「您还不是本店员工」+「申请加入」按钮，填入姓名与岗位，写入 `staff_applications`，由 Web 后台审批
- 角色变更后需重新进入小程序才生效（避免运行中权限抖动）

### A1 桌况总览

- **两种视图**：网格（默认，适合 10~40 桌）、列表（桌数多时按区域分组）
- **每个桌格显示**：桌号（大字）、状态色条、待接单数徽标、开台时长（超过 90 分钟变橙）
- **状态色**：空闲（灰）、占用无新单（蓝）、有待接单（红闪）、待清台（黄）
- **顶部**：区域筛选、搜索桌号、右侧铃铛（未读提醒数）
- **快捷操作**：长按桌格弹出「清台 / 换桌 / 查看订单」
- **刷新**：`onShow` 全量拉取 + `watch` 增量更新

### A2 单桌处理

- **会话区**：桌号、开台时间、人数（可选录入）、已付总额
- **订单列表**：每个订单一张卡，显示状态、金额、菜品明细（默认折叠）
- **主操作按钮随状态变化**：

| 订单状态 | 按钮 |
|---|---|
| 已支付（待接单） | 「接单」 |
| 制作中 | 「已出餐」 |
| 已出餐 | —（置灰） |
| 待支付 | 「催付」（触发服务号模板消息，需已配置） |

- **其他操作**：清台（校验会话内无未完成订单）、退款、重新打印小票

### A3 订单详情

- 完整明细（含规格、加料、备注）、支付流水号、时间线（下单/支付/接单/出餐）
- 操作：退款（需 manager 权限）、重打印

### A4 沽清 / 上下架

- 搜索 + 分类筛选，列表项右侧一个开关：`在售 / 沽清`
- 沽清后顾客端立即不可点（`getMenu` 走缓存时需带上版本号，沽清后主动失效缓存）
- **完整编辑（改价、改名、换图）不在小程序做**，跳转提示「请在电脑端后台修改」

### A5 设置

- 提醒设置：铃声开关、音量、是否常亮
- 测试响铃（方便开业前验证）
- 退出登录、查看当前角色

## 三、Web 后台（`web-admin`）

| # | 模块 | 核心能力 | 备注 |
|---|---|---|---|
| W1 | 登录 | 账号密码 + 微信扫码登录 | 首次由店主创建 |
| W2 | 菜品管理 | 分类增删改排序；菜品增删改（名称/价格/图片/描述/单位/规格/加料）；批量导入 CSV；上下架；沽清 | 一期重点 |
| W3 | 桌台管理 | 桌号、区域、座位数增删改；单张/批量生成小程序码；下载 ZIP 打印 | 桌号改动需重新生成码 |
| W4 | 订单管理 | 按日期/桌号/状态筛选；详情；退款；导出 Excel | 退款需二次确认 |
| W5 | 打印设置 | 绑定云打印机（SN/密钥）、测试打印、按分类路由到不同打印机 | 如凉菜一台、热菜一台 |
| W6 | 员工与权限 | 审批加入申请、调整角色、停用 | 角色：owner / manager / waiter / kitchen |
| W7 | 数据看板 | 营业额、订单数、热销菜品（**二期**） | — |

### W2 菜品管理的字段级要求

- 价格输入以「元」展示、以「分」存储，输入框限制两位小数
- 图片：单张 ≤ 2MB，上传到云存储，自动生成 200×200 缩略图
- 规格：支持「单规格」与「多规格（如大/中/小、冷/热）」，每个选项可设置加价
- 排序：支持拖拽，写入 `sort` 字段，顾客端按 `sort` 升序
- 批量导入：CSV 模板含「分类、名称、价格、单位、描述」，导入时逐行校验并返回失败行号

### W3 桌码生成

- 调 `manageTable` 的 `genQrcode` 动作，服务端调 `wxacode.getUnlimited`，`scene` 为桌号（≤32 字符）
- 生成的图片存云存储，同时记录到 `tables.qrFileId`
- 批量下载：后端打包 ZIP，文件名 `A08.png`
- **注意**：桌号修改后旧码立即失效，必须重新生成并更换桌贴
